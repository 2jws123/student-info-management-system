# 课程设计日志（第 2 天）

**日期**：2026 年 10 月 13 日　星期二

今天的主要工作是把系统的设计方案定下来，为明天开始写代码做好准备。

上午我们先确定了系统的整体结构，采用三层架构，把代码分成三个包：界面层只管显示和接收操作，业务层负责规则判断和数据校验，数据层负责读写文件。这样分工之后，每个人负责的部分相对独立，改一个地方不会影响别人，五个人也能同时开工。五个功能模块也确定下来了，分别是用户管理、学生管理、课程管理、成绩管理和统计分析，每个模块由一个人负责到底，从设计到编码到自测。

接着讨论数据怎么存。本来考虑用数据库，但装数据库服务器、建表、配连接会占掉不少时间，而且我们这个系统数据量很小，就几十个学生、几十条成绩。最后决定不用数据库，改成用文本文件保存：每个实体存一个文件，一行是一条记录，字段之间用竖线分隔，比如学生文件里的一行是"1|2024001|张伟|男|软件2401|13900000001"，分别对应编号、学号、姓名、性别、班级、手机号。文件用 UTF-8 编码，可以直接用记事本打开看。这个方案的好处是简单、不用装任何东西，坏处是数据量大或者多人同时写的时候会出问题，这一点后面会注意。

下午写数据格式的时候，还定了几条具体的规则：成绩的总评成绩不单独存，而是由平时成绩和期末成绩算出来，公式是平时占百分之三十、期末占百分之七十，这样不会出现存的分数和算出来的分数不一致的情况；用户密码也不存明文，用 MD5 加密成三十二位的密文再存，别人打开文件也看不到真实密码。

界面方面，画了主界面的草图：左边一条深色的导航栏放菜单，上面一条信息栏显示当前登录的人，中间是内容区用来显示各个模块，最下面是状态栏。菜单要根据登录角色动态生成，比如学生登录后不应该看到用户管理这一项。另外大家一致同意界面要做一些效果，比如渐变按钮、圆角卡片、图表动画，这样答辩演示的时候好看一些，也是加分项。

今天还统一了开发环境：都装好了 JDK 17，配了环境变量，IDE 统一用 IntelliJ IDEA，源码文件统一用 UTF-8 编码，另外项目里会自带一份 JDK，这样换电脑也能直接运行，不用重新装环境。

今天遇到的问题有两个。一个是关于要不要用数据库，组里意见不统一，有人觉得用数据库更正规；后来讨论下来认为课设时间只有一周，而且文件存储正好能用上 Java 的文件读写和反射这两个知识点，最后按不用数据库定下来，并且在设计里把数据读写单独放进一个类，将来想换成数据库只改这一个类就行。另一个问题是讨论界面时意见太多，有人说要做得像网页那么花，有人说简单点就行，最后定了个原则：功能优先，特效只做能自己用 Java 画出来的，不引入第三方界面库。

明天的计划是：先把项目框架搭起来，建包结构、写公共的工具类；然后实现登录和主窗口，让大家能登录进去看到菜单；另外我负责的统计分析模块要先把统计数据的方法写出来，其他人开始做自己模块的数据读写部分。
